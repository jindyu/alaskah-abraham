## 2. 헤드리스 브라우저 QA (`node tools/qa/qa-abraham.mjs`, 개발 서버 필요: `PORT=… `)

- 6개 권을 **장 선택 UI(Tab → ArrowRight → Enter)** 로 들어가, 개발 훅 `window.__abraham.state()` 로 **실제로 그 권이 로드됐는지 단언**한다 (이전 QA 는 같은 우르 프롤로그를 이름만 바꿔 캡처했었다). 스크린샷은 `docs/qa/books/book1..6.png`.

## 3. 확인되지 않았거나 부족한 것 (정직한 목록)

- **장 내부 진행은 '입력 재생' 방식으로 복원한다** (`src/game/chapterLog.ts`: 실행한 상호작용 id·선택지 번호를 저장 → 이어하기 때 조용히 같은 순서로 재실행). 확인: 2권 1장에서 돌 1개 줍고 저장 → 새로고침 → 목표가 (1/3)로 복원(헤드리스 브라우저), 단위 테스트는 기록·직렬화·재생 모드만 다룬다. **한계**: 액션이 시간 지연·컷신에 의존하면 즉시 실행으로 대체되고, 1권 우르 통합 루프 등 다른 장의 복원은 개별 확인하지 않았다.
- 1권 우르 공방(도구 장착 흐름)은 자동화로 끝까지 검증하지 못했다.
- **모바일 터치 QA는 에뮬레이션뿐이다** (`npm run qa:mobile` = `tools/qa/qa-mobile.mjs`: 모바일 가로 뷰포트 + 터치 입력으로 터치 UI 7개 요소 표시, 도움말·장 선택·일시정지 메뉴를 탭으로 열고 닫기를 단언, 스크린샷 `docs/qa/mobile/`). 이 QA 가 도움말 단추가 미니맵을 가리던 결함을 찾아 고쳤다. 실제 기기에서의 성능·터치 감도 기록은 없다.
- **프레임당 할당은 여전히 0이 아니다 (실측, 이번 작업 후).** `qa-perf` 가 정지 20초 동안 `JSHeapUsedSize` 증가분을 합산한 추정 할당률은 세겜 ~1.0MB/s, 소돔 ~1.2MB/s, 헤브론 ~1.0MB/s (이전 같은 방식 측정 1.3 / 1.2~3.5(튄 값) / 0.8~1.0 — 측정 잡음이 ±0.3MB/s 라 '줄었다'고 단정할 만큼의 차이는 아니다). CDP `HeapProfiler.startSampling` 으로 12초 샘플링한 합계는 ~1.5MB/s → ~1.2MB/s. **목표였던 ≤0.5MB/s 는 달성하지 못했다.** 구성: Three.js 내부(유니폼 업로드 `setValueM4`·`setValueV3f`·`copyArray`·`flatten`, 렌더 리스트 정렬·`projectObject`)가 ~85%(~1.0MB/s)로, 드로우콜·프레임 수에 비례하며 앱 코드로는 고칠 수 없다. 앱 코드 몫은 ~0.25MB/s 로 전부 이번 작업 범위 밖 파일이다: `hudPanels.ts` `goalPanel`·`drawMinimap`, `pixelText.ts`, `entities/player.ts:453 update`, `systems/interaction.ts nearest`. 이번에 고친 것: `frameLoop.ts` 의 `for...of` 이터레이터(actors/animals)를 인덱스 루프로, 클로저에 잡힌 `let` 타이머(쓸 때마다 힙 숫자 할당)를 `Float64Array` 로, `uiScale.snapRect` 가 매번 새로 만들던 `{x0,y0,x1,y1}`+`snapSpan` 배열 2개를 64칸 풀로, `beam.ts` 의 `for...of` 를 인덱스 루프로. 이 몫들은 프로파일에서 합쳐 ~0.05MB/s 라 총량 변화는 잡음에 묻힌다. 그림자 맵을 격프레임으로만 다시 그리게 했지만(`PixelRenderer.shadowRate=2`) 할당 총량에는 눈에 띄는 변화가 없었다. **CLAUDE.md 규칙 1(프레임당 할당 0)은 코드 전체로는 지켜지지 않고 있다.**

  14개 무대 **모두 ≤170** (최대 mamre 151). 삼각형은 최대 mamre 306k → **279k**, shechem 277k → 246k, beersheba 200k → 183k (14곳 모두 ≤300k). 삼각형은 `VoxelBuilder` 가 같은 배치 안에서 정확히 마주 붙은 안쪽 면(쌓은 박스 사이)을 빼서 줄었다. 쓴 방법: (1) 움직이는 부품(사람·동물의 팔다리처럼 안에서는 정지한 메시 묶음)을 (재질×그림자 플래그) 별로 **뼈 배치**(`staticMerge.ts` `buildBoneMesh`: 정점마다 뼈 번호, 부품당 월드 행렬 1개를 `scene.onBeforeRender` 에서 할당 없이 갱신, 깊이 재질도 같은 변환, 메시당 최대 24뼈) — `SkinnedMesh` 와 같은 원리인데 가중치가 없다. (4) 병합 못 한 작은 메시와 한 부품 묶음의 작은 부품은 그림자 패스에서 뺀다 (큰 3개만 그림자). **타일 24 로는 줄이지 않았다**: 24 로 줄여도 mamre 삼각형은 그대로(306k)였고 ur_workshop 드로우콜만 206 → 231 로 늘었다(48 유지). **한계**: 위 수치는 헤드리스 Chrome(소프트웨어 GL) 의 `renderer.info` 값이다 — 실제 모바일 GPU 시간·발열은 측정하지 않았다. 병합 직후 장 연출이 노드를 바꾸는 무대(palace·esau·siddim)는 병합 이득이 없다.
- **그림자 맵 격프레임 갱신 (`shadowRate=2`)** 은 움직이는 그림자가 최대 1프레임 늦다 (같은 장면에서 1 vs 2 비교 차이 0.000%, 움직이는 장면은 따로 비교하지 않았다). 최악 프레임의 드로우콜은 그대로이고 평균만 줄어든다 — 프레임 시간이 격프레임으로 오르내릴 수 있다.
- **병합·안쪽 면 제거·그림자 컷의 시각 동일성은 자동 검사한다 (`node tools/qa/qa-merge-visual.mjs`, `qa:all` 에 포함 — package.json 스크립트는 범위 밖이라 추가하지 않았다).** 14개 무대마다 병합 관찰이 끝나길 상태 폴링으로 기다린 뒤 시계를 고정(`__abraham.freeze`: dt=0·고정 시각)하고 HUD·플레이어를 숨겨 3D 장면만 비교한다. (a) 같은 무대 같은 순간의 병합 켠/끈(`setMergeActive`) 차이: 14곳 모두 **≤0.003%** (노이즈 바닥 0.000%). 음성 대조군(병합 메시만 지움)은 병합이 살아 있는 무대에서 2.4~25% 로 크게 달라져 비교가 병합 내용을 실제로 본다는 증거다. (b) 그림자 컷 영향 ≤0.003%. (c) 안쪽 면 제거 켠/끈 무대를 각각 새로 지어 비교: 대부분 ≤0.09% 이나 **실행마다 무대 1~4곳이 0.4~0.9% 로 어긋난다** (어긋나는 무대가 매번 달라 면 제거의 결함이라기보다 무대를 다시 지을 때 달라지는 요소 때문으로 보이나 **원인은 확인하지 못했다**; 같은 설정끼리 다시 지은 바닥은 ≤0.05%). 그래서 이 항목은 `qa:all` 에서 **경고만** 하고(`CULL_STRICT=1` 이면 실패), 실패로 치는 것은 (a)(b)와 셰이더 오류뿐이다. 면 제거 자체의 단위 테스트(`tests/static-merge.test.ts`: 쌓은 박스 11면→9면, 떨어진 박스는 그대로)는 통과한다. **한계**: 정지 한 자세 비교이므로 걷는 도중 자세·셰이더 오류는 한 자세만 본다(병합 검사가 셰이더/WebGL 콘솔 오류도 같이 실패 처리). 뼈 배치 정점 셰이더는 `MeshLambert/Standard` 의 `begin_vertex`·`beginnormal_vertex` 를 패치하고 균일 스케일을 가정한다(부품이 비균일 스케일로 찌그러지면 법선이 어긋난다).
- **QA 대기를 상태 폴링으로 바꿨다 (`tools/qa/lib.mjs`).** 고정 `sleep` 대신 `window.__abraham.state()` 가 (권, 장, 무대)와 일치할 때까지 폴링(15초 제한), 실패하면 페이지를 새로 열어 한 번 더, 개발 서버 HMR 로 컨텍스트가 사라지는 오류(`Execution context was destroyed`)는 흡수한다. `qa-stages`·`qa-perf`·`qa-merge-visual`·`qa-visual`·`qa-progress` 의 장 이동과 접속 대기, `qa-abraham`·`qa-furnace` 의 접속 대기에 적용했다. **`qa:stages` 는 연속 3회 통과** (48개 장 도달·화면 48종, 한 회 약 35초; 이전 고정 sleep 방식은 가끔 '이동 실패'). 아직 고정 `sleep` 이 남은 곳: `qa-mobile`(탭 사이 대기), `qa-abraham`/`qa-furnace` 의 키 입력 간격과 연출 대기(애니메이션 시간 자체를 기다리는 것이라 상태로 바꾸기 어렵다), `qa-visual` 의 토스트 소멸 2.5초 — 이 스크립트들은 이번에 3회 반복 검증하지 않았다.
- 다른 에이전트가 같은 개발 서버에서 소스를 고치는 동안에는 HMR 전체 새로고침이 QA 중에 일어날 수 있다 (위 폴링이 흡수하지만 장면 상태는 초기화된다). 측정은 전용 서버(별도 포트)에서 했다.
- 같은 드로우콜 수라도 `qa-perf` 가 재는 값은 **무대를 어느 장으로 열었나**에 따라 달라진다(장 연출이 NPC·소품을 얹음): 이번 측정은 각 무대의 첫 등장 장 기준이다.

- 1~6권 중 37개 장은 직접 쓴 연출 없이 **JSON 대본의 대사만** 패널로 재생한다 (Godot 2D 연출은 3D 에서 재현하지 않음). 보이스는 한국어 모드에서만 재생한다.
- 비주얼: 2~6권 무대와 시간대 프리셋은 크게 좋아졌지만, 큰 벽·지붕 면의 텍스처 디테일, 캐릭터 모델 다양성, 환경 파티클은 부족하다.

- 상호작용이 없어 '다음 이야기로' 안전망만 있던 2~6권 장 중 7곳(2권 5·9장, 4권 5장, 5권 5장, 6권 3·4·6장)에 단계형 짧은 루프를 추가했다 (`beatLoop.ts`, 영어 포함). 헤드리스 브라우저로 상호작용 등록은 확인했지만 사람이 끝까지 플레이한 검증은 없다. 1권 7·8·10·12장(궁정·풀무불·하란·에서 진영)에도 `book1Beats.ts` 로 같은 루프를 추가해 **브라우저 스캔 기준 안전망뿐인 장은 0개**다. `tests/beat-reach.test.ts` 가 11개 장의 모든 상호작용이 충돌로 막힌 자리에 있지 않은지 단언한다 (이 테스트가 실제로 막힌 자리 5곳을 잡아 옮겼다).

대단원 맺음말이 선택에 따라 달라진다(`epilogueFor`, `storyFlags.ts`): 한 선택의 성향(담대함·맡김·돌봄) 중 가장 많은 것을 따라 제목·문구가 바뀐다(동률은 돌봄>맡김>담대함, 선택이 없으면 기본). 브라우저 확인: 궁정에서 ‘담대히 선포’ 선택 후 아우트로 끝에서 ‘대단원 · 담대한 믿음’ 표시. 맺음말 문구만 바뀔 뿐 엔딩 장면 자체가 갈라지지는 않는다. → 이제 성향이 있으면 대단원 배너 전에 성향별 맺음말 자막 세 줄(`epilogueLines`)이 재생되고 끝나면 배너를 띄우고 처음으로 돌아간다(브라우저에서 ‘담대한’ 성향의 첫 줄 재생 확인, 나머지 두 성향은 단위 테스트까지만).

`hudDialogue.ts` 의 매 프레임 그리기 경로에서 배열을 새로 만들던 곳(대사 줄 `map`/`Math.max(...)`/`forEach`, 시네마틱 제목 `split`)을 모듈 버퍼·루프·글이 바뀔 때만 다시 계산하는 캐시로 바꿨다(렌더 결과 동일, 스크린샷 확인). `hud.ts` 의 `clearToast`/`say` 의 `.filter` 는 이벤트 때만 불려 그대로 뒀다. 프레임당 할당 0 이 코드 전체로 지켜진다는 뜻은 아니다(Three.js 내부 몫이 큼 — 위 측정 참고).

대단원 맺음말을 제목 문자열 비교가 아니라 `dominantTrait`(성향) 로 정하게 고쳤고(제목 문구를 바꿔도 자막이 비지 않음), 선택지 패널의 매 프레임 `choiceOptionRects = []` 를 `length = 0` 로 바꿨다.

`createGame.ts` 에서 챕터 대본 재생(지연 로드·한 번 재시도·장 바뀜 가드)과 전승 안내를 `chapterPlayback.ts`(`createChapterPlayback`)로 분리해 923→879줄로 줄이고, 이전에는 클로저 안이라 테스트할 수 없던 로직을 단위 테스트 7개로 지킨다(성공·busy·장 바뀜·cancel·재시도 후 실패 알림·전승 안내·인트로/아우트로 건너뜀).

`hudDialogue.ts` 의 그리기 경로에 남아 있던 `forEach` 클로저 5곳을 `for` 루프로 바꿨다(시각 회귀 0.03~0.74% 로 렌더 결과 동일).

도움말 패널 아래에 ‘저장은 자동’·‘선택은 이후 장면에 영향’ 두 줄을 더해 비어 보이던 아래쪽을 채웠다(터치·데스크톱 스크린샷 확인, 겹침 없음).

`hud.ts` 에서 메뉴 클릭 처리(`hudClicks.ts`)와 월드 위 하트·말풍선(`hudWorld.ts`)을 더 분리해 1098→995줄로 줄였다(처음 2178줄). 모바일 QA 의 탭 동작·진행 QA·시각 회귀가 모두 통과해 동작과 화면은 그대로다.

`save.ts` 의 남은 빈 catch(가져오기 첫 쓰기·보관본 정리·`.prevAt` 표시)도 `noteSaveError` 로 연결했다. 27차 감사: 구성 7.6·사용성 7.4·안정성 7.3·콘텐츠 7.7·비주얼 6.8 (콘텐츠 7.7 은 지금까지의 최고값).

목표 패널 레이아웃 캐시의 키를 매 프레임 만드는 템플릿 문자열에서 숫자·문자열 필드 직접 비교로 바꿨다(`goalPanel`, 프레임당 문자열 할당 제거). 목표 문구·진행도가 바뀌면 다시 배치된다는 동작은 진행 QA·시각 회귀로 확인.

28차 감사(구성 7.6·사용성 7.7·안정성 7.3·콘텐츠 7.6·비주얼 7.0)는 사용성 7.7 이 최고값이다. 같은 감사에서 ‘panelToggles 테스트가 없다’는 지적은 사실과 달랐다(`tests/panelToggles.test.ts` 5개). 감사자는 얕게 읽었다고 스스로 밝혔다.

영어 번역이 없던 장 요약 16개(1권 노아의 저주, 2~6권 주요 장 등)를 번역해 넣었고, 요약이 있는 모든 장이 영어 번역을 갖는지 검사하는 테스트(`tests/summaryEn.test.ts`)를 더했다. 이제 영어 모드의 장 선택 화면에서 장 요약이 한국어로 남지 않는다.

나무 수관(`buildFoliageTree`)을 잎 복셀 0.28→0.24, 덩어리 2→4개, 거칠기·구멍을 높여 ‘둥근 공’ 대신 가지마다 잎뭉치가 달린 들쭉날쭉한 윤곽으로 바꿨다(헤브론 스크린샷 확인, 스테이지 빌드 테스트 시간 변화 없음, 시각 회귀 기준 갱신).

29차 감사(구성 7.5·사용성 7.7·안정성 7.3·콘텐츠 7.8·비주얼 7.0, 콘텐츠 7.8 이 최고값)가 지적한 `touchControls.ts`·`portraits.ts`·`fx.ts` 의 진단 기록 없는 `catch` 7곳을 `noteError` 로 연결했다.

HUD 메뉴 클릭 처리(`hudClicks.ts`)에 단위 테스트 9개를 더했다(`tests/hudClicks.test.ts`): 닫힌 메뉴가 클릭을 삼키지 않음, 장 선택의 바깥·✕·권 탭·장 고르기→다시 눌러 이동, 일시정지 항목·바깥, 도움말 닫기, 도감의 실제 index, 선택지 콜백·바깥 클릭 삼킴. 이전에는 이 로직을 브라우저 QA 로만 확인했다. 그리기 코드 자체의 단위 테스트는 여전히 없다.

30차 감사(구성 7.6·사용성 7.7·안정성 7.2·콘텐츠 7.6·비주얼 7.0)가 지적한 대로 `getPick`/`setPick`/`getTrait` 타입이 액션 모듈마다 따로 선언돼 있던 것을 `systems/actions/pickTypes.ts` 한 곳으로 모았고, `HAGAR_SENDOFF` 는 공통 꼬리 문장에 앞부분만 붙이는 방식으로 바꿔 문구가 어긋나지 않게 했다(문장은 그대로, 브라우저 확인).

남은 진단 기록 없는 `catch` 25곳(`lang`·`textSize`·`saveLock`·`safeStorage`·`fatal`·`input`·`audioManager`·`cutscene`·`appearance`·`pixelRenderer`)을 모두 `noteError` 로 연결하고, 앞으로 `catch {` (오류 변수 없는 catch)가 생기면 실패하는 테스트(`tests/noSilentCatch.test.ts`)를 더했다. 삼켜도 되는 오류를 ‘왜 삼켰는지’ 나중에 알 수 있게 하는 것이며 오류 처리를 대신하지는 않는다.

31차 감사(구성 7.8·사용성 7.4·안정성 7.3·콘텐츠 7.8·비주얼 7.0)가 지적한 `.play().catch(() => {})` 3곳을 `noteError` 로 연결하되, 브라우저가 자동 재생을 막는 정상적인 거절(`NotAllowedError`·`AbortError`)은 기록하지 않게 걸러(30개짜리 기록이 소음으로 차지 않게) `noSilentCatch` 테스트에 이 형태도 포함했다. 선택지 안내의 `[↑/↓]` 가 작은 글씨에서 `[1/1]` 처럼 읽힌다는 반복 지적에 `[위/아래]` 로 바꿨다.

**8점 목표는 달성하지 못했다. 감사 점수는 라운드마다 ±0.5 흔들리며 5개 항목 모두 6.5~7.5 사이에 머물러 있다 (감사자는 게임을 실행하지 않고 코드·스크린샷만 본다).** 6차 감사자는 정수로 채점했고 감사 범위가 앞선 차수보다 좁아(스크린샷 일부만 확인) 차수 간 직접 비교는 정확하지 않다. 지적: `hud.ts` 2178줄·`createGame.ts` ~1050줄, 50장 중 21장이 대사 전용 재생, 모바일 버튼 밀집, 장 내부 복원의 실제 장 재개 테스트 부재, 전승 안내 문구 반복.

감사자는 매번 이전 점수를 모른 채 채점했다. 3차 이후에 한 수정(액션 루프 런타임 테스트, 타이머 취소, 장 건너뛰기, 번역 스캔 등)은 아직 재감사하지 않았다.

- **성능**(`tools/qa/qa-perf.mjs`, 무대별 최댓값): draw call 최대 281→248(ur_workshop), 마므레 218→130, 소돔 159→105. 정적 메시 병합(`staticMerge.ts`) + 매 프레임 `getProgram` 재계산을 일으키던 투명 DoubleSide 재질 수정. 정지 20초 잔존 힙 증가 0.03~0.07MB(누수 없음), 할당률 약 1.0~1.4MB/s(이전 약 2.4~2.7MB/s, 같은 방법). 삼각형은 병합으로 5~15% 늘었다. 예산: draw call 280, 삼각형 40만, 잔존 1MB, 할당률 2MB/s(부하에 따라 요동).
- **콘텐츠**: 대사 위주였던 장 18개에 연출 추가(`staging.json`), 자막을 JSON 데이터로 이동, 4권3·5권1에서 이전 선택에 따라 소품·대사가 달라짐, 에필로그 여정 결산. 연출 자막은 원 대사를 요약한 것이라 기존 대사 패널은 해당 장에서 재생되지 않는다.
- **알려진 한계**: 병합의 시각 동일성은 자동 검증하지 못했고(노이즈 1.4~7%) 시각 회귀·눈 확인으로 대신했다. 3·5권 연출은 목표 문구로 장을 판별해 취약하다. 실기기 검증은 없다.
